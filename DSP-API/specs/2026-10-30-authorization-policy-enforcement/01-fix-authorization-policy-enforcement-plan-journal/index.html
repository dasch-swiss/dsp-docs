    Closeout

    • root_cause: dsp-api endpoint bases only authenticate. Authorization was a hand-called check per RestService or responder, across about 13 overlapping mechanisms, with nothing tying an endpoint to a required role. A check could be missing (@unused user, DEV-7713; anonymous-only check, DEV-7714; ingest report), swallowed (.ignore on the anonymous check), given the wrong identity (SystemUser reads, DEV-7712 and DEV-7723; a user IRI passed as a project IRI, DEV-7721), or inverted (DEV-7722), and every one of them compiled and passed the tests.
    • investigation: Red runs corrected three plan claims. Project history with a hidden resource answered 403, not 500, because checkResourceIris refuses before .resources.head. Anonymous resource creation already got 403 from the later create-permission check, so only the message and the check order changed. The ingest report answers 202, not
    • DEV-7721 and DEV-7722 were masked by comparePermissionsADM, which gives SystemAdmins and ProjectAdminAllPermission holders the maximum on both sides. DEV-7722 became red-testable only after the comparison was made replaceable in tests.
    • solution: Eight fix: commits, one per gap, plus a shared custom-permission ceiling helper. Then ADR-0013: a declared Policy attribute on every endpoint, set by policy-declaring BaseEndpoints factories. Project-scoped policies hand the handler a ProjectCandidate that only AuthorizationRestService.authorizeProjectAdminById turns into a ProjectAdminGrant, which the migrated domain writes require. A ratchet test pins the unpoliced baseline at 175 endpoints and lets it only shrink. A lint in just check fails on @unused User parameters and on new SystemUser uses (10 allow-listed files). The admin lists and v2 standoff pilots are migrated, with node-to-grant checks inside the per-node lock, and an authorization matrix e2e spec acts as an independent oracle.
    • prevention: Forgetting the project check on a migrated endpoint no longer compiles (compile-negative test). A new endpoint without a policy fails EndpointPolicyE2ESpec. Ignored users and new SystemUser elevation fail the lint. Anti-patterns to avoid: reading as SystemUser before a permission check; .ignore on a check effect; validating request shape before authorization when the answer leaks object details; String IRI overloads in role checks. Follow-ups: migrate the remaining slices (DEV-7725); the DEV-7718 count endpoints; lint rules for ensure*ProjectAdmin*, Policy.key and withInfo outside slice.common.api.
