    Side findings

    • Phase 1: review (dune): ServiceTokenVerifier is injectable from any slice via SecurityModule.Provided; ADR-0014 should state that only the BaseEndpoints policy factory calls it, ideally with a lint ratchet like api_imports (Phase 2/5).
    • Phase 1: review (dune): EdDsaJwt.verify checks no claim while the sibling JwtCodec.decodeAll does; the jwt boundary rule in ARCH-MAP should say only ServiceTokenVerifier calls it. Name kept as the plan specifies.
    • Phase 1: review (dune): the JSON-in-one-string setting is parsed in slice/security, not in AppConfig's .validate chain (which would make app depend on security); ADR-0014 should record it as a deliberate exception.
    • Phase 1: review (scala-zio): if externalKnoraApiBaseUrl cannot be normalised every token is bad_audience with no startup hint; a startup warning when keys are configured would help. Not reachable with the current URL builder.
    • Phase 1: review (security): base64url signature has 4 malleable trailing bits; harmless while nothing keys on the raw token string. Duplicate JSON keys resolve last-wins consistently. Phase 2 must sanitise an unverified kid before logging it (P9 logs only a configured kid, so this already holds by design).
